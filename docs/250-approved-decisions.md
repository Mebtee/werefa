## Purpose (full column contract)

Each decision in this register must eventually have:

| Column                     | Description                                      |
| -------------------------- | ------------------------------------------------ |
| **Decision ID**            | Stable identifier `DEC-001` … `DEC-250`          |
| **Decision statement**     | The exact approved wording of the decision       |
| **Domain**                 | The documentation domain the decision belongs to |
| **Source/question number** | Original source/question number if known         |
| **Status**                 | Import / approval status                         |
| **Requirements affected**  | The `REQ-*` requirement(s) derived from it       |
| **Notes/conflicts**        | Conflicts, duplicates, superseded relationships  |

---

## Register Conventions & Status

1. **All 250 decisions (`DEC-001` … `DEC-250`) are APPROVED** unless a later instruction explicitly changes one.
2. The **exact original wording** of the 250 decisions has **not yet been supplied** to the documentation.
   - Do NOT guess. No decision statement is invented.
   - Every slot below therefore carries: `STATUS: NEEDS SOURCE DECISION TEXT`.
3. Approved **decision content** that has been supplied (the confirmed product facts from the requirements sessions) is captured verbatim in **Appendix A** using `KF-<GROUP>-NNN` identifiers.
   - Do NOT assume each `KF-*` fact corresponds 1:1 to a single `DEC-*` number. Several facts may trace to one decision, or one fact may span several decisions.
   - Mapping `KF-*` facts to `DEC-*` slots is performed **during decision import** when the source text is supplied.
4. Conflicts and duplicates are recorded explicitly (never discarded). See [Known Decision Conflicts](#known-decision-conflicts) and the notes in Appendix A.
5. This register tracks **decisions**. The Master Specification (`01-master-specification.md`) remains the source of truth for **requirements**. Requirements are derived after import.
