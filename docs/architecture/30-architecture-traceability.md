> Binding: complete requirements set of Werefa v0.5.0 (232 formal REQs) mapped to the architecture. Decision resulting from mappings used: see the architecture docs themselves.

## 1. Method

- Source of truth for requirement text: `docs/01-master-specification.md` (Werefa v0.5.0).
- Every requirement REQ-001..REQ-232 is mapped to the architecture: an architectural component, the design document(s) that implement it, the critical invariant the design guarantees, and the test strategy that verifies it.
- Decision-register mapping status is **preserved exactly**: 208 requirements remain `PENDING DECISION REGISTER MAPPING`; 22 are `RESOLVED — PROMPT 05-FIX`; 2 (REQ-159, REQ-160) are `DEC-175`. No DEC-001…DEC-250 mapping was invented or implied here; see `docs/decision-traceability.md`.
- Where a requirement is satisfied purely by existing UI or by the operational/process layer with **no new architectural component**, it is still mapped (with a note) and counted separately below (≈5); the coverage goal is 232/232 mapped.
- Any contradiction or architecture issue discovered during mapping is reported in section 5 (zero raised during authoring).
